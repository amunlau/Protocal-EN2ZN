# 长文档、样本与分批流程

## 解析与清单

**建正文清单前必须完成 [水印与页眉页脚专项处理](pdf-furniture.md)。** 分别保存原始提取、正文候选和排除记录；已确认水印与重复页眉页脚不进入术语和翻译。疑似对象须核验，禁止固定裁边、全局删词和按重复直接删除。章首页、奇偶页、横向页单独判断，保护脚注、表头、真正标题与跨页正文。

每个排除对象保存页码、ID、原文/图像位置、分类依据、核验记录和清洗版本；每页保留与排除对象合计覆盖原始提取对象。这个核对不替代对原始 PDF 提取遗漏的视觉检查。inventory 只能从核验后的保留对象建立，记录 processing_sha256；不能直接把 pdf_probe 原始文本当正文。

先计源文件总页数，再记录翻译范围；源文件 ≥20 页须样本确认，不能人为拆文件绕过。页数未知时禁止批量翻译。

`pdf_probe.py` 逐页缓存并支持续提，但不识别版面语义。先查看原生文字、结构树及几何，局部 MCID 标签不能替代完整读序。多栏、跨页表格、公式、图和脚注须对照页图核验。仅对缺失或不可靠区域补 OCR，保留原图、坐标变换和核对记录；检查 0/O、1/l/I、负号、比较符、上下标和单位。提取空文本不能直接判断空白页。

先按章构建、保存目录与索引，再汇集为 inventory.jsonl。每行一个逻辑块，ID 稳定、顺序唯一；source 是原文而非摘要。保存 section、pdf_pages（1 起算）、printed_pages（可罗马数字）、kind、source、protected、term_ids。复杂块补 structure、parent_id、dependencies 及 [文档模型](document-model.md) 的来源区域/样式。旧 source_bbox 可作为证据保留；新输出按经过验证的坐标约定读取，不能混用不同解析器的原点、单位或旋转状态。

维护 coverage.json：翻译范围的每页、实质区域均关联内容块，或记录按约定保留、排除或待核的理由。图片区不能因其图题有块就视为全部覆盖；图内独立标签须列入。脚本能检查块清单对应，不能单靠块数证明原始 PDF 没有漏提取。原文快照登记后不可静默改写；提取纠错需新修订项目和迁移记录。

表格保存单元格 ID、行列、合并范围、原文及脚注绑定。续表连接成逻辑表，重复表头统一译法；超长表按行组拆，附相同表头和单位，禁止从单元格句中切断。图片保留图号、源图与坐标；图题、图注、图内标签分别登记。不可编辑的图保留原图并附有定位的中文标签对照。

新表格和图内标签用 [segments 载荷](project-state.md#逐段逐格绑定)；空单元格也有 ID。段落级 ID 用于追踪，翻译批次可以含多个相关段落；不能误把每个稳定 ID 当成必须孤立翻译的一句话。清洗后原文、结构、术语与渲染输入形成同一条可回溯路径，避免排版时另抄一份译文。

正文块通常约 800–1500 个英文词，依复杂度缩小并给审校留余量。完整句、条款、公式及定义尽量不拆；超长条款采用共享父 ID 的子块，邻接上下文只供参考，避免重复输出。不得把全部 2000 页文字或图像一次载入模型上下文。

## 样本

水印/页眉页脚存在时，样本必须覆盖对应页面和实际存在的误删风险（脚注、表头或页顶正文等），对照清洗前后的页图验收。

通常对应 3–5 页原文：连续正文加代表性规范语气/技术论证、术语及实际复杂结构。技术文档覆盖彩底、反白字、图内标签或合并表等代表项；论文覆盖切栏、公式、引用或脚注等代表项。说明选择理由和未覆盖难点；不能只取封面目录。范围过小时可用范围内全部实质内容。

样本使用最终输出的约定，附源页码、关键术语、版式与待确认选择；先做语义与两种版面审校。新项目默认同一份审定内容生成 DOCX 和保版式 PDF，两者一起登记和交付；用户指定单格式时只要求该格式。Word 预览 PDF 与保源版式 PDF 区分标识。状态与命令见 [台账](project-state.md)；样本文件、选段、译文或重要约定变化按实际影响重新确认。证据保存真实用户回复、时间及版本，不得模拟用户同意。

旧 DOCX 项目沿用已登记输出和有效批准，不因为安装新版本或换工具自动升级为双输出。用户扩展 PDF 时登记输出变更，完成新增格式样本/版面验收；保留历史批准和审定译文。单纯移动相同字节文件不构成新样本。语义 policy 与输出约定分别更新，避免改列宽导致全篇译文重新审校。

样本交付后紧接的明确“继续”可结合语境作为批准；新会话的“继续翻译”不能补齐不存在的批准记录。批准后样本译文直接复用。

## 每批上下文与恢复

每批读取源版本、章节路径、约定版本、相关术语与定义、必要的前后文、匹配已审译文和未决依赖。全库检索用于定位，不把全部命中载入。

`next` / `show` 提供当前有效审校记录的有界 TM 候选，突出相同原文的多译法，以及近似候选中的数字、否定、模态差异。候选带来源、语境和版本，仅为 `reference_only`；不能自动提交或批准。索引命中不足时按概念/章节另行定位，不把检索上限内“没有冲突”解释为全库一致。完整上下文优于仅提高匹配分数；这一原则参考 [OmegaT 的默认与替代译文机制](https://omegat.sourceforge.io/manual-standard/en/chapter.how.to.html)。

记录本批输入/输出 ID、相关定义、约定版本与实际完成边界；发生输出截断时保留完整已提交块，重试未完整块，不凭末尾省略号补齐。表题与表体、标题与首段、续句及其脚注尽量同批；上下文片段标 `reference_only`，核对组装时不重复输出。

逐批检查前批末尾与本批开头：跨页连词/否定是否丢失、指代是否改换、列表引导句是否仍支配后续条目、相同表头单位是否延续。遇到后文定义改变前文术语理解，用依赖记录回查，不仅修改后续翻译。

先审技术含义，再审中文。为每条要求核对主体、动作、条件、强度、否定、范围、例外；为技术/学术论断核对证据强弱、比较基线和测量口径。跨节引用记录目标和依赖，最终核验目标存在。

诊断应指出源片段、译片段、问题类别及建议的最小修改，修订后重查受影响的保护项和依赖。可借鉴 [translation-agent 的初译—诊断—修订流程](https://github.com/andrewyng/translation-agent)，但不固定模型、不以增加轮数证明质量；高风险块优先独立核验，没有新证据不无限重写。背景只用已核对的定义和上下文，不把模型生成的摘要当作源事实。

草稿也及时提交。中断恢复先核验源哈希、数据库完整性、样本确认与已提交内容；先接着审未审草稿，再翻未完成块。操作中的块恢复为待译或待审，不能跳过。见 project-state.md。

逐章/逐批解析、翻译、审校与渲染，保存缓存和分章成果。分别记录 Word/PDF 的生成、渲染和验收状态，共用审定译文版本；一种成功不代表另一种完成。失败页单独记录，可推进无依赖章节，但不能从分母移除。运行额度或工具限制到来前保存当前完整块并备份，说明下一位置。关机后需用户重新启动任务，不能承诺关机期间仍运行。

2000 页能力指可分批、可检索、可恢复；实际耗时与质量取决于源文件。模拟规模测试不等于真实全文翻译验收。内置输出器目前一次处理项目完整范围，并非流式分卷引擎；大型输出使用具备分章/分卷能力的适配器，从统一台账生成并合成，再对完整产物验收。不能把台账扩展性当作 DOCX/PDF 输出内存上限的证明。

记录提取/OCR/布局引擎版本、配置、字体和生成器版本。提取或清洗结果改变已登记原文/结构时须新建源修订；仅换提取器重建缓存、且核实登记内容未变时，不改写原清单或无故废弃已有批准。清洗约定的实际变化仍按语义约定关口处理。仅排版工具改变可复用已审译文但重做受影响版面验证；翻译模型改变不自动使既有已审译文失效，也不能把缓存复用报成重新翻译。恢复时脚本重跑确定性检查，有新未处置项才转回待审，不清空旧译文。

性能优化按页/区域路由：原生可读文本不整页 OCR；重型布局/数学模型仅用于需要的区域；图片资产复用但核对出现位置；处理和渲染使用有界批次，失败只重试受影响单元。缓存键包含源哈希、解析/清洗版本、相关约定和生成配置，不能仅用英文字符串复用不同语境的译文。不同字节但相似文字/页图只作为迁移候选，不能绕过源身份核验。

对小批已完成结果可用 `batch-commit`（上限与载荷格式见台账指南）减少重复源文件核验和事务开销；仍由一个协调者写入，一项失败整批回滚，样本和非样本不可混批。它不自动翻译、不减少语义审校，也不改变关机关联的持久化保证。索引是可重建派生数据，源快照、译文与真实确认仍是恢复依据。

## 全项目一致性审计

合成前跨章节检查，不能只在各批内部看重复。运行只读工具，报告保存到项目内新版本路径：

```text
python /absolute/path/protocol-en2zh/scripts/consistency_audit.py --project /absolute/path/项目 --output /absolute/path/项目/qa/consistency-v1.jsonl
```

样本阶段加 `--sample`；只比较当前有效已审内容，不让候选检索成为提前翻译非样本的途径。默认最多输出 500 组、每组 6 个实例，可用 `--max-findings` / `--max-examples` 调整；汇总仍列全范围候选组数及是否截断。报告绑定源、清单、内容、语义约定和审校资格快照；译文/审校/检查版本变化后重新生成，不能套用旧结论。

重点核对同源异译、异源同译，以及首次解释缺失、重复或晚于先前使用。要求 `first_use` 的术语，明确标注为 `translate` 的实例也参与首次位置检查；不能只因所有实例都译成中文而漏掉未完成首次解释的约定。采用磁盘临时索引，不把全书源译装入内存；按文档身份、版本、文体、角色和显式语义约束分组，不按大小写折叠或删空白把不同机器标识合并。叶子单元格分别审计；父块术语实例等未覆盖项在计数中标明，另做人工核查。工具不推断自然语言 scope；摘要、正文或分册各自首次解释可能合法。未审、失效或有开放待核项的记录不进入可复用候选，无候选不证明全书准确。候选逐项处置到审校记录，再对改动块重审；不盲目统一所有同形词。机制参考 [Weblate 的双向一致性检查](https://docs.weblate.org/en/latest/user/checks.html) 与 [Okapi 的源译对应检查](https://okapiframework.org/wiki/index.php/Quality_Check_Step)。

## 解析与性能的实际验收

接入或升级后端时，用同一小组代表页比较：单栏/双栏切换、扫描混排、旋转/裁剪、短标签、表格合并/续表、彩底反白、公式符号、脚注多引用、链接及重复 OCR 层。分别记录漏译/错译和条件强度错误、结构缺失、版面缺陷、耗时与峰值内存；不以单一分数掩盖关键错误。[COMET](https://github.com/Unbabel/COMET) 等模型可选用于筛查，须校准语言与领域、核对输入一一对齐，不能把得分换算为本项目准确率或代替人工接受标准。

外部解析任务清单记录请求页范围、实际完成页、跳过原因、partial/timeout/error、任务 ID/cursor、版本/配置和产物哈希。检查后端是否默认只取前几页、跳过短文本/已有文字页、关闭表格或公式；返回文件或进度 100% 不等于完整提取。客户端超时先查询原任务，不能重复启动整篇。按页像素和批次设置预算，后台进程失败只重试有关区域；不以降低所有页 DPI 来掩盖资源问题。[OCRmyPDF](https://ocrmypdf.readthedocs.io/en/latest/advanced.html) 的跳页/超时和 [Docling](https://docling-project.github.io/docling/reference/pipeline_options/) 的部分成功状态均需按此契约核验。

本地辅助工具还不是强隔离的解析调度器；不承诺恶意或畸形单页的硬内存上限。对重型任务使用宿主实际支持的独立工作进程、超时和资源监测；PyMuPDF 不在多线程间共享 Document，按[官方并行建议](https://pymupdf.readthedocs.io/en/latest/recipes-multiprocessing.html)各进程独立打开。避免多层并发叠加，先按小批测本机。模型实例可按配置复用，但内存增长时有界重启工作进程，不导入未经验证的私有补丁。
