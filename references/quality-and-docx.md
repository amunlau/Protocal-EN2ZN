# 质检与 Word / 保版式 PDF 交付

## 分类与记录

参考 MQM，采用 accuracy、terminology、normative-force/claim-strength、numbers-identifiers、structure、Chinese-style、layout。论文/报告额外检查论断强弱、统计与比较口径、引用归属。额外细分与验收阈值属于本项目约定，不称为 MQM 官方认证。

每问题保存 ID、块/页/单元格、原文与译文、类别、严重度、原因、建议及处置。

- critical：要求/禁止、否定/条件、关键数值/位域/互操作行为或主要结论改变，或实质内容遗漏。
- major：术语错误、表格错位、引用错误或影响理解的歧义。
- minor：不影响技术含义的表达/版面问题。

未解决 critical/major 不得标审校通过；minor 交付时明列。脚本只能校验记录存在和确定性差异，不能证明审校者实际完成语义审查。

## 每块与全文检查

**水印与页眉页脚专项验收是交付前必检项**，按 [专项规则](pdf-furniture.md) 核对排除清单、正文来源和版面。检查已确认水印是否泄漏为中文正文、图注、术语或翻译记忆；检查页眉/页脚是否夹断句段、生成伪标题或进入表格单元格。反向检查被排除内容，确认真实标题、脚注、续表表头、警告、公式与页底正文未误删。发现泄漏或误删须修正并重审受影响块，不能以译文流畅放行。

1. 原文清单覆盖正文、表格单元格、图题/图注/图内标签、脚注、代码注释、附录及范围内声明；一块有译文仍需检查块内漏句。按约定保留的英文与未译叙述分开核对。
2. 检查数字多重集、单位、版本、位号、范围、上下标、公式、保护标识符及重复次数。数字相同但交换行列无法靠多重集发现，须按位置核对。
3. 检查规范性语气/论断强度、否定和条件，不以关键词计数直接判语义正确；论文核对证据、因果/相关及研究局限，技术报告核对测试和比较口径。
4. 术语须匹配 scope/sense；约定变更后既往审校也可能失效。
5. 核对表格行列、跨度、表头单位、保留位与脚注；底色、粗体和统计标记若承载意义也须对应；公式和代码不改运算关系。
6. 单独记录中文行文审查；润色后再核查技术含义未变。

合并与交付前运行 `scripts/consistency_audit.py`（见其 `--help`），或从同一台账执行等效的跨章节检查。脚本只输出同源异译、异源同译及术语首次解释作用域三类候选，数值等风险特征仅供对照；同义术语/DNT、数量归属和引用语义仍须逐块及全篇人工核对。记录实际范围和候选处置；不自动改译文、认定错误或代替批准。

工具输出 findings，由审校者逐条修复或解释误报；禁止无依据批量忽略。result.issues 保存未决问题，review 必须记录语义、中文、结构检查及 findings 的处置。

原文到译文逐条查漏；译文到原文逐条查无依据增写。对技术含义先作判断，再审中文；每次润色后重查受影响的条件、否定、语气、数值与引用。表格按 ID 核对数值属于哪个对象、单位与脚注，不能只比较数字集合。数学符号改写成中文时可能有自动误报，只有等价且符合项目约定才可解释放行。

审查记录区分模型自查、独立模型检查和领域人工审校，写实际使用者与覆盖范围。同一模型扮演多个角色不称为独立验证。回译和模型评分可定位疑点；流畅、回译相似、多个模型赞同、BLEU/COMET 等分数均不能覆盖一个关键要求反转。无需为每块强制回译，也不引入未经验证的“准确率 ≥99%”门槛。方法参考 [专业译者的上下文与错误评估研究](https://aclanthology.org/2021.tacl-1.87/)；其结果不代表当前模型或本技能的准确率。

发现系统性错误（如 should 全译成应、同类图内标签漏译、页脚误入正文）时回查全篇同类用法；不把局部修复当作全篇通过。批量确定性检查覆盖全部块，语义审校逐块完成；版面缩略图筛查与放大检查分别记录，不能把抽样说成逐字通审。

## 共同来源与两种输出

只从同一份审定内容与关联结构生成输出，不让 DOCX 和 PDF 后端分别调用模型再译。记录源哈希、内容/审校版本、输出约定版本、生成器/字体和实际检查范围。逐块/逐格对账允许明确记录的空白、换行与分页变化，不允许数字、归属、引用或限定条件改变。

语义约定与输出格式/样式分开登记，具体命令见 [项目状态](project-state.md)。修订译文后两种输出均须更新；仅改列宽/颜色时可复用已审译文，但受影响输出必须重新生成与验收。文件存在、渲染成功和一个解析器分数均不等于通过。

Word 默认保留可编辑内容与逻辑结构；PDF 尽量保持原始页面和栏位。源版式约束与中文可读性冲突时，先局部流排/调整空间，再按约定处理字号、续表或续页，记录差异；不得删文、改数、压缩表达或以整页截图充当可编辑 Word。Word 导出的预览 PDF 是 DOCX 的渲染证据，不自动满足保源版式 PDF 的要求。

## DOCX

使用可用的文档生成、编辑和渲染能力；有文档技能时按其指引，不能假设固定安装路径。台账工具本身不生成 Word。

- 文首说明源文件/版本、范围、非正式译本、术语表与待核单位置。默认中文正文，对照版按用户要求。
- 页眉/页脚使用 Word 独立区域与项目样式；源文重复页眉页脚不变成正文，不逐页翻译。源图内可见水印不译为标签；保留源图时说明其仍可见，不声称已完成图像去水印。
- 使用原生 Heading 1–9，保留原编号，防止手工编号与自动编号叠加；更深层级保留文本编号与导航结构。
- 中文宋体或等价字体，西文按约定；东亚字体显式设置并检查替代。代码、字段用等宽。
- 表格明确列宽、横/纵合并、重复表头和跨页策略；逐格保存水平/垂直对齐、底色、边框、内边距和局部字体样式，不默认全部居中。过宽表用横向节，不缩到不可读。保留空单元格、保留字段和绑定脚注。
- 图表题保留原编号，图片清晰；不可编辑标签附定位译注。公式优先可编辑，不能可靠还原则用清晰原图并说明。
- 引用使用稳定书签 ID；原文页码引用注明“原文第…页”，不能混作中文页码。
- 分章合并时检查样式、列表、书签唯一性、图片关系、目录、页眉页脚和分节符；采用可靠合并工具或从统一数据重建，禁止直接拼接 XML。
- 论文用分节/分栏表达双栏与通栏的切换；避免用大量浮动文本框模拟正文而破坏编辑和读序。复杂区域确需专用布局时记录边界并核验。

### 中文分页与复杂结构

- 使用样本批准的统一样式，按实际中文、数字、西文和公式宽度试排。溢出先流排、调列宽/方向、拆为有续表标识的逻辑部分或增加页面；不得缩译、删限定词或逐页缩小正文来凑英文页数。
- 检查中文行首行尾标点、成对括号、破折号/省略号分离及孤行。数字与单位、符号与下标尽量同处；标识符/路径不插入会改变内容的空格或软连字符。长标识符优先扩宽、横向或调整专用样式。W3C clreq 是排版需求参考，不把其草案当作协议强制规范。
- 标题与后文、图与图题使用局部“与下段同页”；不要整章串接此设置造成大块空白。短段可段中不分页，长段允许合理分页，避免全局固定行高裁掉公式上下标。
- 跨页表头须为表格最前面连续的行；不能仅给中间一行设重复。短数据行可禁止跨页，长于一页的行须设计分组/续行方案，不指望 `cantSplit` 自动解决。保持行列标题、合并跨度、单位、空格、脚注和分组线关系。
- 横向节前后核查纸张方向、页眉页脚继承与页码连续性；图注不要漂到下一张图前。时序图/位域图保留比例、连线、箭头和位序，不能由生成式重画替换技术原图。
- Word 域与目录在最终合并后更新，并检查错误书签、目录页码与交叉引用。没有实际更新能力时交付说明其待更新状态；最终渲染和正文数据需为同一版本。

排版后从 DOCX/渲染件回抽正文和表格，与已审数据按块/格对账；允许记录清楚的空白和分页差异，不忽略运算符、上下标或内容顺序。回抽只能发现部分问题，仍需看页图中的重叠、裁切、缺字和错误图示。排版与分页属性参考 [中文排版需求](https://www.w3.org/TR/clreq/)、[python-docx 段落属性](https://python-docx.readthedocs.io/en/latest/user/text.html)、[重复表头](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.tableheader?view=openxml-3.0.1) 和 [表格行拆分](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.cantsplit?view=openxml-3.0.1)。

样本全部渲染并逐页检查。最终按章渲染，检查全部页面缩略图/自动溢出结果，详细查看各种版式、复杂图表、合并边界及异常页；记录实际查看范围。无渲染能力则标“版面尚未验证”，不能以文件存在代替。

## 保源版式 PDF

使用源坐标与原始图形资产构建输出副本，保留原件。页面尺寸、CropBox/MediaBox、旋转和坐标变换必须统一；不要把 OCR 像素坐标直接当 PDF 点。源字体可能只含英文子集，目标中文须选择含所需字形的字体并检查嵌入/替代；字体名称相同不保证字形覆盖或分页一致。

1. 核验全部受改区域的中文完整性、字号、换行、栏界、背景色、文字色和行间空间，检查局部粗体/斜体随语义对应。
2. 彩底、反白表头、透明叠层和曲线不能用统一白矩形覆盖；必须保护背景、表线、图线与公式。无法分离时换受支持方案或保留待核，不能静默擦图。
3. 图内标签、行内公式、上标引用和表格数据分别绑定；对需要原样保留的变量/代码/专名核对大小写与数量。
4. 检查未翻译短标签、被跳过的大页面/旋转文本、截断和溢出。渲染器缩小后“放得下”不代表字号可读；处理失败返回值或缺块须阻断对应输出。
5. 回抽输出文字并检查复制/搜索顺序。清点隐藏 OCR、旧英文、重复文字、ActualText/标签与可见译文的不一致；原文保留区和双语版按约定区分，不全局删英文。
6. 检查书签、超链接、引用目标、页码映射与图表数量；保存文档结构与链接能力不足时明示，不宣称已具备完整无障碍结构。

审定译文回填适配器必须对当前源和块 ID 精确匹配；只有英文字符串相同不够。公式/样式占位符、分段与顺序在回填前后守恒，不允许失配后自动调用另一模型重译。BabelDOC 等后端的接口、选项和格式支持随版本变化，接入前固定版本并试验目标结构；不能以其 demo 代替项目验收。

## 内置受限输出适配器

建清单前先确定可用输出路径。同页跨栏的单段、跨页表格、代码和预格式内容常超出单矩形回填能力，应提前选择专项适配器，不能在已登记后为了迎合工具随意拆改原文。内置 PDF 拒绝代码/算法/预格式块、Tab 和连续空格，避免 HTML 流排改变缩进；不得删除这些空白以绕过检查。计划中的文字块顺序必须与台账逻辑读序一致。

`scripts/render_translation.py` 提供无需再译的基本输出通路，输入是项目台账和显式 `PLAN.json`。它不从 PDF 自动推断整页排版，也不取代专项公式、图形或复杂版式适配器。现版本仅对 table v1 消费 `segments`；图内标签或普通段落使用的其他逐段结构仍需专项适配器，不能删除绑定或伪装成表格来通过输出。先用真实代表区域试排，检查所需字段确实被当前版本消费；文档模型允许保存的字段不等于所有输出器均支持。

计划最小示意如下；源哈希、块 ID、页序和矩形须替换为本项目已经核验的数据，不能照抄坐标。样本计划只含已登记样本块，完整计划覆盖当前全部块，每个文字/表格块恰好一次。`unit_id` 绑定已审译文，计划中不重新填写或改写译文。DOCX 与 PDF 可使用不同布局计划，但必须绑定同一份审定内容；不要为共用计划而丢弃其中一种格式需要的样式。

```json
{
  "version": 1,
  "source_sha256": "<源文件的64位SHA-256>",
  "title": "非正式中文译本",
  "pdf_pages": [1],
  "min_scale": 0.9,
  "blocks": [
    {
      "type": "paragraph",
      "unit_id": "p1",
      "style": {"font_size": 10.5, "align": "left", "color": "#000000"},
      "pdf": {"page": 1, "bbox": [72, 100, 300, 180]}
    }
  ]
}
```

- 通用：`version` 固定为 1；`source_sha256` 绑定台账源文件。`blocks` 的 `paragraph/table` 绑定 `unit_id`，`image/section` 仅为布局对象，不能代替文字清单。`style` 使用文档模型字段；尺寸和自定义字段不自动获得排版支持。计划、输出块、PDF 位置和 `exclude_text` 中未知或不适用字段会拒绝，不会当作已消费的设置静默忽略。
- DOCX 段落可用 `heading_level`（1–9）、`page_break_before`、`runs`；每组 runs 的文字拼接必须逐字等于审定译文。分节块可用 `columns`（1–3）、`new_page`、`page_size`（point）。这提供基本分栏，不能保证复杂浮动图表自动落到原位置。
- DOCX 表格必须是 [table v1](document-model.md)；`column_widths` 为每列 point 宽，`header_rows` 为最前面的连续表头行数，`cell_runs` 按单元格 ID 指定局部样式。支持矩形合并、水平/垂直对齐、底色、四边边框与内边距；仍须在实际 Word 渲染中核验。段落/单元格 runs 支持 `font_name/font_size/bold/italic/color/background`，单元格边框和内边距不能拿来控制普通段落。
- DOCX 图片用 `asset: {"path":"assets/figure.png","sha256":"…"}`、`width`（point）和非空 `preservation_note`；资产须在项目内且哈希匹配。说明图内文字与水印处置，不能以插图掩盖漏译。PDF 路径保留原页图形，不把这个图片块当作图内文字替换指令。
- PDF：`pdf_pages` 为唯一且递增的源 PDF 页序（从 1 开始）；段落 `pdf` 与表格逐格 `pdf_cells` 给出 `page/bbox`。矩形使用当前未旋转页面的左上角 point 坐标，须先核验裁剪和坐标变换。表格 `pdf_cells` 包含空单元格，不仅是有字的格子。内置路径拒绝任何跨页 unit；须在清单阶段规划可核验且保留关联的子块，已登记块按修订规则迁移，或直接使用支持多区域的其他适配器。
- PDF 将区域内提取文字与台账原文匹配时，只去掉首尾空白并把连续空白折叠成一个空格，不删除全部空白；`1 0` 不等于 `10`，`m s` 不等于 `ms`。原文校正时可提供 `source_text` 和非空 `mapping_note`，保留校正依据。不能用该机制随意扩大覆盖区域。相交区域、切过邻接字形、缺字形、旋转页、行内占位符和放不下的译文会失败，需修正或换受支持方案。此空白规则仅用于源区域匹配；产物 `content` 回抽仍按台账规则严格对账。
- PDF 的 `runs/cell_runs` 仅支持 `font_size/bold/italic/color`，仍须逐字等于台账译文；字体由 `--font` 明确选择，`font_name` 不另切换字体。背景和边框保留源页面图形，并非按 `background/borders` 重新绘制；`padding` 须体现为已核验的矩形留白，不能直接传给 PDF 样式。局部字体切换、背景重绘或更复杂富文本另用适配器。
- `exclude_text` 只适用于已经核验的原生文字对象；每项含 `id/page/bbox/source_text/classification/evidence`，类别为 `watermark/header/footer/page_number`。它不识别图片/矢量水印。页眉页脚的实际保留或替换服从输出约定，不能只因不进入正文便全部删除。
- PDF 按最多 64 页的连续区间先复制选页，共用源资源映射，再执行回填。删除完成后按显式源页→输出页映射恢复可解析链接、书签和原文页标签，避免逐页复制丢跨页跳转或重复嵌入相同资源。范围外链接不误连到其他页，范围外书签保留为无跳转标题，并在回执列明；书签标题与链接热区分别保留原文和源坐标，中文导航及热区匹配仍须另验。外部文件目标保留原路径，未复制目标文件；相对路径须按新产物位置另行核验。
- 源中存在 OCG 可选图层、无法完整解析的书签、GoToR 外部 PDF 目标或其他未支持导航动作，或选页包含交互表单、尚未应用的 redaction 删除注释时，内置 PDF 输出明确拒绝。已解析成明确内部页与坐标的命名导航可转换为普通 GoTo；原命名目录不复制，外部 `#nameddest` 入口不保证有效，未解析命名动作仍拒绝。不能让翻译删除操作顺带执行源文件已有的删除注释。原标签树与嵌入附件不重建，回执记录其来源状态；有这些结构不代表输出已保留完整无障碍、附件或文档级语义。能力边界依据 [PyMuPDF 页面复制](https://pymupdf.readthedocs.io/en/latest/document.html#Document.insert_pdf) 与 [删除注释行为](https://pymupdf.readthedocs.io/en/latest/page.html#Page.apply_redactions)。

命令中的脚本、项目、计划、输出、字体均用真实完整路径；以下变量指向这些路径，适用于实际宿主的 Python 调用方式：

```text
python "<skill>/scripts/render_translation.py" --project "<项目>" --plan "<计划.json>" --format docx --output "<项目>/sample/sample-v1.docx" --sample
python "<skill>/scripts/render_translation.py" --project "<项目>" --plan "<计划.json>" --format pdf --output "<项目>/sample/sample-v1.pdf" --sample --font "<本地中文字体文件>"
```

完整输出去掉 `--sample`，须先通过适用的样本关口；输出新版本使用新路径，不覆盖旧产物。可用 `--artifact-id` 指定台账产物 ID，省略时使用 `sample-docx/sample-pdf/full-docx/full-pdf`。PDF 通路另需当前适配器要求的 PyMuPDF 和本地中文字体，不因此把重型解析/OCR 后端设为必需。`min_scale` 是试排缩放下限，默认 0.9；不应为通过生成而持续降低，字号可读性仍须视觉验收。

生成器核验源文件/内容/输出约定，在项目内保存产物与 `.receipt.json` 并登记台账；PDF 回执另含 `source_to_output_pages` 和 `navigation`，记录导航保留/范围外目标及结构局限。随后仍须完成 `render/content/visual` 三阶段证据，才能进入样本登记或交付验收；回执不是批准。`render` 的真实 PNG 页图结构校验按需导入 Pillow；当前 pdfplumber 依赖已包含它，仍须确认运行台账的解释器可用。原生 PDF 路径保留背景、图线与图像，不重建完整标签树；未映射区域仍为原文，搜索复制、引用链接、阅读顺序和覆盖清单必须另检。部分样本页中未译的周边原文需明确标明为范围外内容，不能声称该页已全文翻译。

发布使用同目录硬链接，原子占用全新的产物和回执路径，已有文件不会被替换；文件系统不支持硬链接时明确失败，改用支持的本地输出目录。普通生成/登记异常会清理本次发布且文件身份与哈希仍匹配的文件，保留其他写入者替换的文件。强制关机或终止可能留下未登记产物、回执或临时文件；重启先 `resume` 核对台账，不凭文件存在判定完成。保留遗留文件供核验，以新路径重新生成未登记成果；有效登记和检查仍按原版本复用。文件发布与 SQLite 提交不是一个原子事务。

内置生成器的 `full` 是项目当前完整范围，尚不是流式分卷引擎。加载该范围数据前，SQL 检查最多 10000 块、源/结果 JSON 合计最多 32 MiB；Word 单表 `rows × columns` 最多 20000 格、同次输出累计最多 50000 格，按合并前网格计算。这些是拒绝过量任务的界限，不是内存上限或 2000 页输出实测保证。超过时使用支持分卷的外部适配器，从同一台账按块 ID 生成章节，再合成为完整产物并登记整体验收；不删块或把章节文件冒充全范围 `full` 成品。分批解析、翻译与恢复能力仍按长文流程执行。

## 可选后端与能力边界

轻量原生解析优先，困难区域才启用布局/OCR；高复杂度文档可选 Docling、PaddleOCR/MinerU，论文引用可选 GROBID，保版式输出可评估 BabelDOC/PDFMathTranslate-next。所有选择都须实际检查当前版本、输出字段和本机能力，不要求安装全部工具。

保留完整结构化结果及源对象属性；普通 Markdown 只可作为阅读视图，不能成为还原底色、合并、位置和复杂样式的唯一输入。某后端提供 Word 导出并不证明其样式忠实，提供置信度也不证明每格正确。能力与局限依据：[Docling 结构](https://docling-project.github.io/docling/concepts/docling_document/)、[PaddleOCR 结构化输出](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/PP-StructureV3.html)、[GROBID 坐标](https://grobid.readthedocs.io/en/latest/Coordinates-in-PDF/)、[BabelDOC 接口与选项](https://github.com/funstory-ai/BabelDOC)。

复杂表格验收分别看结构、单元格归属和样式；文本、公式与阅读顺序也分别检查。可借鉴 [GriTS](https://arxiv.org/abs/2203.12555) 与 [OmniDocBench](https://github.com/opendatalab/OmniDocBench) 的维度，但不要求运行整套基准，不把解析成绩或自拟用例通过率当翻译准确率。

## 交付关口

核对源清单及翻译范围的覆盖，包括保留/排除理由；适用时有覆盖约定格式的有效样本批准。全部块 reviewed 且关键/重大问题清零，才能称语义审校通过；两种输出分别完成对应版本的检查，才能称全部交付完成。否则明确待审范围和缺失格式。合并后核查顺序、缺块、重复块、图表/公式数量和版面。备份项目并交术语、审校、待核及输出记录，让用户能脱离原聊天续做。
