# 中文翻译、规范性表达与术语取舍

## 依据与适用范围

协议模式借鉴 GB/T 1.1 中文表达习惯、ISO 条款分类和源协议约定，不把外国协议重新起草成国家标准。技术报告、白皮书和论文采用 [对应文体规则](document-types.md)，不机械使用规范性词表。技术语义以指定版本的源定义、适用引用和具体上下文为依据。中文术语优先用户已确认的项目约定；与源定义冲突时列待核。不混用不同版本或不同概念的译名。

## 先分类规范性语气

协议及确有规范性功能的段落，先记录源文对 shall、must、should、may、can、optional 的定义及大小写规则。以下按功能给出默认中文，不能把单词表当作自动替换规则；例外写入项目约定。

| 源文功能 | 默认中文 | 必查事项 |
|---|---|---|
| shall；被定义为要求的 MUST/SHALL | 应 | 不译成“将”“宜” |
| shall not；被定义为禁止的 MUST NOT/SHALL NOT | 不应 | 不弱化为“不建议”；采用“不得”需项目统一 |
| should / recommended，表示推荐 | 宜 | 不提升为“应/必须” |
| should not / not recommended | 不宜 | 不误作绝对禁止 |
| may，表示允许 | 可 | 与可能性区分 |
| need not，表示无要求 | 不必 / 无须 | 不等于禁止 |
| can，表示能力 | 能 / 能够 | 不当作许可 |
| may / might / can，表示可能性 | 可能 | 不增加保证或必然性 |
| must，表示外部约束或不可避免情形 | 必须 / 按语义确定 | ISO 与 IETF 体系不可机械通用 |

只有源文件采用相应体系时才用其规则；RFC 8174 的大写条件不能推广到所有硬件规范。普通叙述的 will、is、supports 不自动升级为“应”。may not 的“不允许”与“可能不”须结合语境区分。

逐项保留 if、only if、unless、except、until、at least、at most、exactly、either、both、respectively 的范围与逻辑。核查 and/or 结合关系。注和示例即使存在原文写法疑点，也要忠实翻译并另记问题，不能擅自删除要求或移入正文。

对复杂要求先记录“谁—在什么条件/状态下—应/宜/可做什么—对谁—何时—限制与例外”，再组织中文；这个记录用于审查，不增写进正文。尤其检查 `not all`（并非全部）与 `none`（全无）、`only if`（必要条件）与 `if`、`unless` 的例外范围、`not ... until` 的时间边界，以及 `respectively` 的逐项对应。前置条件移到句首时须覆盖原来相同的动作，不能只限定并列动作中的一个。

协议常见的 `reserved`、`undefined`、`unspecified`、`implementation-defined`、`implementation-specific`、`deprecated`、`obsolete` 分别按源定义建概念，不一概译成“无效/未定义”；`assert/deassert` 不自动等于置 1/清 0，先核查有效电平；`set/clear`、`read-to-clear`、`write-one-to-clear`、`reset value` 的主体和触发动作不能互换。缩写同形、状态名与普通词同形时以字段/状态定义为准。

## 中文行文

- 优先清楚的“条件—主体—规范性动词—动作—约束”，仅在原文可明确确定时补出省略主体。
- 自然使用“当……时”“仅当……时，才……”“除……外”“见……”“按……规定”；按逻辑选择，不无差别替换。
- 减少空泛的“进行……的操作”“被……所……”，保留技术动作；长句可在同一条款内分句，但限定、因果、并列关系不能改变。
- 专业术语不用同义词轮换。定义保留所属类别及区别特征，不补入原文没有的定义。
- 机器可识别的寄存器/字段、状态、信号、命令、包类型等标识符保持大小写和拼写；周围叙述可译。普通名词并非一律不译。
- 按术语策略选择中文、保留原文或首次解释；不要求所有术语首次都中英并列。首次解释的位置按最终文档阅读顺序确定，摘要、正文和独立分册是否分别解释在约定中明确。
- 叙述用中文标点；代码、公式、位域、路径、标识符与数值内部保持原始符号、进制、前导零、大小写和全半角。
- 不换算数值与单位，不修改规范版本。`0x10`、`10h`、负号、比较符、上下标均要保护。
- 默认不插入解释性扩写。确需解释歧义、图内标签时，用明确“译注”与原文条款分开。

中文润色专查长“的”字链、空泛名词化、无主句指代、重复代词、不自然搭配和被动语序。可以用动词直述动作，但不能为“去翻译腔”删除具有逻辑作用的连接词、条件或主体；同义词替换不适用于已锁定术语。连续多条要求保持主语可辨，避免“其/它”指向不同设备。

## 自拟例句（不是引用的协议原文）

| 英文 | 中文 | 检查点 |
|---|---|---|
| If Ready is 1, the receiver shall accept the packet. | 当 Ready 为 1 时，接收端应接收该包。 | 条件、字段值、要求 |
| The sender should retry after 10 ns. | 发送端宜在 10 ns 后重试。 | 推荐与要求区分 |
| The device may omit this field. | 设备可省略此字段。 | 前提是许可意义 |
| The device may fail to respond. | 设备可能无法响应。 | 可能性不是许可 |
| The receiver need not retain the value. | 接收端无须保留该值。 | 无要求不是禁止 |
| The bit shall be cleared only if both conditions hold. | 仅当两个条件均成立时，才应清零该位。 | 不把必要条件增写为充分条件 |

## 术语与变更

术语条目至少有 `id / en / zh / sense / scope / status / forbidden / source`。同形异义分配不同 ID。candidate 保留待核；核实的 provisional/confirmed 可进入活动约定。scope 记录文档领域、层级与语境。

新增条目使用 `strategy` 明确取舍，缺省 `translate` 以兼容旧项目：

| 策略 | 决策与检查 |
| --- | --- |
| `translate` | 使用适用的中文译名；定义、术语与普通描述仍须按语境区分 |
| `retain` | 原文保留；登记产品/模型/数据集/标识符等理由，保护大小写和字符，不能成为整段漏译的豁免 |
| `first_use` | 指定首次实例使用约定的中英表达；后续实例按确定的动作处理，不随批次/重启重新解释 |

`case_sensitive` 可显式指定；缩写 CAN 与普通 can、模型名与普通名词不能折叠匹配。自动词面命中只生成候选，最终按实际出现位置绑定术语实例；`term_occurrences` 的区间与动作、旧 `term_ids` 的兼容检查见 [文档模型](document-model.md)。一个块内同时有同形异义或首次/后续用法时，必须使用实例绑定，而非仅对整块绑定一个词条。源文本修订后重新定位，不能套用旧字符偏移。

保留策略不等于“不需要审校”；检查使用理由和是否属于确实应该翻译的叙述。未知缩写先查源定义，不凭字母猜全称。首次中英并列的“首次”按摘要、正文、分册等约定作用域计算，不按模型当前上下文计算。依据：[微软术语管理](https://learn.microsoft.com/en-us/globalization/localization/managing-terminology) 中的概念、语境与 DNT 管理；不采用其中针对营销改写的建议来改动源技术内容。

译前查源定义、邻接上下文、活动术语、已审译文。翻译记忆要同时核对版本、主体、条件、否定和数字；近似匹配只是建议。中文目标词出现不等于用法正确。

通用术语库仅提供候选：优先核对源定义和用户约定，再查同领域正式中文资料、术语数据库或厂商原始文档。搜索命中数不等于独立证据；多个网站转载同一译法仍是一条来源。一个可靠且适用的定义胜过多个跨领域词典命中。记录检索词、来源位置、适用版本和选择理由。

匹配时优先完整短语和适用概念，防止将 `virtual channel` 中的 `channel` 当成另一独立译法；保护标识符大小写不折叠。词形、别名与缩写显式登记；自动边界匹配只是候选，不能自动消除同形异义。按实际语境绑定 `term_ids`，再检查所有出现位置；首次中英并列的“首次”按最终文档/分册顺序计算，不按本批模型上下文计算。

翻译记忆只把已审、同版本/语境可用的条目作为强参考。相同英文在正文、字段名、图例或不同时期版本中可能不同义；近似匹配特别标出 changed number / negation / modal / condition。用户已修订译文优先保留，改动只覆盖受影响范围，不能整章重译抹去审定措辞。

复用时同时看出处、源版本、章节/角色、术语概念、邻接上下文和审校状态；多个精确候选不同译时展示分歧，不能静默取最新一项。近似建议未修改并不必然错误，但数值、否定、规范动词或条件已变而仍照搬旧译时须专项核对。CAT 的“100%/上下文匹配”是检索类别，不是准确率；机制参考 [OmegaT 的默认与替代译文](https://omegat.sourceforge.io/manual-standard/en/chapter.windows.and.dialogs.html)、[memoQ 的上下文/多译法记忆](https://docs.memoq.com/12-5/en/Concepts/concepts-translation-memories.html)。

跨块另查两类候选：相同原文是否出现不必要的译法漂移，不同原文是否被复制成相同译文而丢失差别。先按文档身份/版本、局部文体、正文/字段/图例角色和显式概念分组；只有词面相同而语境不同，允许译法不同。不同英文的相同中文也可能正确。审计报告只定位候选，不自动全局统一；[Weblate](https://docs.weblate.org/en/latest/user/checks.html) 和 [memoQ QA](https://docs.memoq.com/12-5/en/Workspace/edit-qa-settings.html) 都将这些关系作为需要判断的检查。

首次解释审计按最终阅读序与约定作用域进行：术语 ID、scope、最早实例、后续动作、首次定义所在块都应可定位。摘要、正文、独立分册是否分别解释由项目明确；自然语言 scope 不足以让脚本自动推断边界。恢复、分批或换模型不重置首次状态，后文另义使用新的概念 ID。术语表中的 first_use 和单块“同时出现中英文”不足以证明整个文档首次解释正确。

URL、DOI、邮箱、命令选项、路径、转义按机器字符串核对，不用普通中文润色规则改写。优先显式保护；自动发现差异只作候选，不能把示例变量、数学除式或 LaTeX 命令误判成漏译。[文档模型](document-model.md#机器字符串与异常字符) 给出可选来源区间和异常 Unicode 诊断。机器串字面一致仍不证明引用到了正确对象。

使用已批准样本中的少量源译片段校准文体，记录样本版本和适用场景；不得虚称未经用户审定的例子为金标。审校先给原文片段、译文片段、问题类型与依据，再做必要的最小修订；无问题可以保留原译。润色之后重新检查限定词、主体、保护项和术语，不以反思轮数、自评分或“更像中文”代替含义核对。可借鉴 [translation-agent 的诊断/修订分离](https://github.com/andrewyng/translation-agent/blob/main/src/translation_agent/utils.py)，其作者明确这是示范工作流，并非稳定优于其它方法的证明。

新增不冲突术语可持续增补；改变已用译法时记录理由、旧值、新值、受影响块，并重审、重生成相应章节。不能把改术语表当作改完历史译文。
